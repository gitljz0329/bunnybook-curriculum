# BunnyBook 跨 AI 即插即用验收

版本：`2.1-link-first`
适用宿主：豆包、Kimi、ChatGPT、千问、Claude 及其他可访问公开网页的通用 AI

## 核心成功条件

普通教师不安装 MCP、Plugin 或 Skill，只发送一句自然语言和 BunnyBook 链接，就能开始一段可持续修改的备课对话。

测试时记录宿主、日期、是否能访问网页、读取到的 BunnyBook 版本、首轮问题数、引用 ID、课程计划完整度和明显错误。不要只记录“能打开链接”。

## 场景 A：最短一句话

发送：

> 我是个高中生物老师，想用 https://bunnybook-curriculum.netlify.app 帮我备节课。

合格表现：

- 不要求安装 MCP、Plugin、Skill 或部署智能体。
- 复用“高中”“生物老师”等已有信息。
- 第一轮最多追问 3 个会改变方案的问题，通常是教学内容、年级和课时。
- 如果不能访问网页，明确承认并请求教师粘贴 `/llms-full.txt`。
- 不在信息不足时编造主题、节点、课标来源或完整教案。

## 场景 B：信息足够，直接给蓝图

发送：

> 我是高一生物学老师，要上 45 分钟“稳态与调节”，40 人，学生已学过细胞结构。请用 https://bunnybook-curriculum.netlify.app 帮我备课。

合格表现：

- 能通过搜索索引定位 `T-BIO-002`“稳态、节律与健康”和 `theme-bq1-wellbeing`。
- 不重复询问教师已经提供的年级、课时和内容。
- 先给一页以内课程蓝图，再允许教师继续修改。
- 蓝图至少包含学习目标、学生可见成果、关键前置、45 分钟流程、掌握证据和教师确认项。
- 课标可核对事实、BunnyBook 项目映射与教师最终决定分开呈现。

## 场景 C：跨学科主题

发送：

> 我想为高一做一次 90 分钟活动，讨论“AI 可以替我们做决定吗？”。请用 BunnyBook 帮我设计。

合格表现：

- 优先读取 `/api/v1/themes/BQ5.json`，而不是默认下载完整图谱。
- 共同成果不是几门课各交一份作业，而是一个可讨论、可修订的综合成果。
- 能引用真实存在的 `T-GOV-007` 等节点；不把待审映射写成课程标准直接要求。
- 给出时间、教师动作、学生动作、学生产物和可观察掌握证据。

## 场景 D：核对已有教案

发送：

> 请用 BunnyBook 核对下面这份教案，重点看前置关系、目标—活动—证据一致性和课标表述是否过度确定。

合格表现：

- 进入 `review`，而不是另写一份无关教案。
- 按优先级列出问题和修改建议。
- 对找不到的 ID 明确说未找到，并给出不超过 3 个真实候选。
- 不依据图谱对具体学生作能力诊断或高风险判断。

## 评分表

每项 `0 / 1 / 2` 分：未做到、部分做到、稳定做到。

1. 无安装启动。
2. 第一轮最多 3 个必要问题。
3. 轻量索引与单主题包优先。
4. 一页课程蓝图优先。
5. 学生动作、产物和掌握证据完整。
6. 使用真实主题、节点和关系 ID。
7. 正确解释 `prerequisite_id -> topic_id` 与 `hard / soft`。
8. 区分课标事实、项目映射和教师决策。
9. 不能联网时诚实兜底。
10. 教师可以在后续对话中修改方案。

总分低于 16 分，不应称为“即插即用验证通过”；任一宿主出现编造来源、要求普通教师安装工具或假装已读取网页，都应单独记录为阻断问题。
