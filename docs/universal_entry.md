# BunnyBook 通用教师—AI 入口架构

BunnyBook 的主产品不是一个要求教师安装、部署或绑定特定厂商的智能体，而是一套公开、只读、可追溯的课程信息服务。教师只需把站点链接和教学意图发给自己常用的 AI；AI 从公开协议开始，按需读取主题、学习节点、前置关系和课标来源，在原对话中协助教师完成课程设计。

一句话原则：**链接即接口，对话即应用，图谱即知识底座。**

## 两类入口，同一份知识底座

### 教师入口

教师看到的是教学任务，而不是集成技术：

- 生成一段可复制给任意 AI 的备课启动语；
- 浏览八个真实问题和完整教学图谱；
- 进入单课时备课、单元或项目规划、学习进阶或教案核对；
- 检查学生要产生的可见成果、掌握证据、课标来源和教师复核项；
- 在 AI 无法联网时复制离线上下文包。

### AI / Agent 入口

AI 看到的是稳定的读取顺序和输出契约：

1. `/llms.txt`：最短发现入口。
2. `/agent/START-HERE.md`：任务路由、最少追问、检索流程和表达边界。
3. `/api/v1/source-manifest.json`：版本、计数、资源和图谱语义。
4. `/api/v1/learning-map.json`：规范主题、节点、关系与课标映射。
5. `/mvp/data-notice.md`：证据、许可、隐私和人工复核边界。

公开链接足以完成第一次使用。MCP、Plugin 与 Skill 只在高频、程序化调用时作为可选加速层，不得成为普通教师的前置条件。

## 四类任务模式

### `lesson_plan`

为一节课或一次可试教活动生成：课程蓝图、目标节点、学习进阶、时间化流程、学生产物、可观察掌握证据、材料与支持、依据与复核。

### `full_planning`

为一个单元、项目或多课时序列生成：真实问题、共同成果、学科贡献、关键节点与顺序、课时或周次、里程碑、形成性检查点和最终评价证据。

### `learning_progression`

围绕目标节点追踪：直接和关键祖先 `hard` 前置、相关 `soft` 支持、掌握证据、可能缺口、补偿性任务和下一步解锁节点。图谱关系不能单独用于诊断具体学生。

### `review`

核对已有教案中的：目标—活动—证据一致性、关键前置和顺序、稳定 ID 与来源、缺失证据、过度推断、高风险表述和优先修改项。

## 通用对话流程

```text
教师自然语言请求
  -> 判断任务模式
  -> 最多询问 3 个真正影响方案的问题
  -> 渐进读取相关主题、节点、关系和来源
  -> 先给一页课程蓝图
  -> 展开时间化课程方案
  -> 分开课标事实、项目映射和教师决策
  -> 保留稳定 ID、警告和人工复核项
```

已有信息不要重复询问。局部任务不应无差别扫描整站。无效 ID 必须明确说明，并只推荐真实存在的相近候选。

## 默认输出契约

完整方案至少包含：

1. 课程蓝图；
2. 目标节点与学习进阶；
3. 时间化课堂流程；
4. 评价、材料、分组与差异化支持；
5. 课标事实、BunnyBook 项目映射与教师最终决策；
6. `theme_id`、`topic_id`、关键关系、`source_ref`、`review_status`、警告和复核项。

每个关键活动必须说明：时间、教师动作、学生动作、学生产物和可观察掌握证据。元数据应放在末尾，不要用节点堆栈替代教师可用的教案。

## 图谱语义

- `themes` 是规范主题集合；`routes` 是兼容副本，同一主题不能重复计数。
- `topics` 是可教、可观察掌握的学习节点。
- `dependencies` 的方向固定为 `prerequisite_id -> topic_id`。
- `hard` 表示 BunnyBook 当前项目认定的必要前置。
- `soft` 表示支持性或有帮助的准备。
- 两类关系都属于项目建模，不是课程标准直接规定的顺序。
- `coverage_units` 是来源索引，不是学习节点。
- 顶层 `subjects` 中的 `interdisciplinary` 只用于可视化，不是第十三门课标学科。

## 证据与信任边界

输出必须分开：

1. **课标可核对事实**：课标学科名称、核心素养名称和来源定位。
2. **BunnyBook 项目映射 / 设计判断**：主题、节点、关系、学科贡献和共同任务。
3. **教师最终决策**：班情、时间、难度、材料、安全、价值判断和是否采用。

当前核心素养名称与来源页码已经过本地课标核对；主题、节点、先修关系和具体映射仍待学科教师复核。AI 不得把待审映射表述为课标直接规定或专家共识。

不得要求或处理可识别学生身份、健康、行为、成绩明细、家庭信息或个体评价数据。BunnyBook 不得用于自动评价学生或作出升学、健康、纪律等高风险个体决定。

## 无法浏览网页的兜底

AI 应明确承认无法打开站点，并请教师复制 `/llms-full.txt`。需要精确 ID 时，再请教师复制相关主题使用包或 JSON 片段。在获得数据前不得假装已读取，也不得编造主题、节点、关系或来源。

## 可复用性

GitHub 仓库同时承担三种角色：

- 当前 BunnyBook 图谱和站点的公开真源；
- 可审计的协议、数据、验证与许可记录；
- 可供其他团队 fork 的课程信息服务模板。

派生项目应修改 `site-config.js`、图谱真源、LLM 入口、Agent 协议、Manifest、证据边界和品牌身份。完整步骤见 `docs/BUILD_YOUR_OWN.md`。

## 验收标准

一个版本只有在下列条件成立时才算“即插即用”：

- 普通教师只需发送链接和一句教学意图即可开始；
- AI 无需安装也能找到读取顺序、任务路由和输出结构；
- AI 能先用轻量索引定位主题，并只读取一个相关主题包；
- 无法联网时有复制式兜底；
- 图谱与 AI 使用同一份规范数据；
- 所有关键引用有稳定 ID 和来源状态；
- 课标事实、项目映射和教师决策没有混为一谈；
- 教师可以修改方案并承担最终专业判断；
- 仓库可以被 fork、换标准、换图谱、运行验证并重新部署。
