# 产品方向修正：给教师看的图谱，给 Agent 调用的课程信息源

## 最终产品定位

本项目不是教师、学生、Agent 三类用户并列的平台，而是“一位教师、两层产品表面”：

1. **教学图谱**负责吸引教师、解释一个跨学科主题为何成立，并让教师核对共同任务、学科贡献、节点关系和课标依据。
2. **Agent 接入**负责真实使用，把选中的主题或节点作为可追溯信息源交给教师已有的备课 Agent。

机器层以同一份 `learning-map.json` 为唯一完整本体：静态 manifest 负责发现，真实只读 MCP 负责运行，目标宿主 Plugin 只做适配。学生任务、表现证据和工作纸仍然是教师设计活动所需的数据，但学生不再是独立界面入口。

主站对外的一句话卖点是：**让你的备课 Agent 不再凭空编课。** 图谱与 MCP 都是实现机制；教师真正得到的是一套可追溯、可复核、能够进入已有 Agent 的课程上下文。

部署前的转化路径固定为：`选择真实问题 -> 查看共同任务与学科协同 -> 复制零安装 Agent 使用包 -> 验证输出价值 -> 再配置本地 MCP / Kimi Code 第三方插件`。公开静态站不运行 Python；远程 MCP 仍明确标识为尚未开放，Kimi 适配只称“第三方 Custom Plugin 本地测试包”，不能称官方插件或已上架。

## 这次偏差发生在哪里

上一版 MVP 的工程管线是完整的，但产品对象选错了：页面把 Big Questions、主题、活动任务、课标锚点和评价证据放在同一套交付视图里，最终更像“两套教师共备样张的控制台”。

参考产品真正有价值的部分并不是 3D 效果，而是四个相互咬合的产品承诺：

1. 一个节点只表示一个可学习、可判断掌握的微主题。
2. 一条边只表示清楚、有方向、有理由的先修关系。
3. 点击节点后，整张图围绕“前面需要什么、后面解锁什么”重新组织注意力。
4. 主题不是一组节点的标签，而是“一个真实问题、多门学科分工、一个共同表现任务”的学习单元。

因此，本项目不再把“已有多少文档、主题和活动”当作 MVP 完成度，而改用“用户能否沿学习依赖关系探索和作出判断”验收。

## 产品层级重新分工

| 层级 | 核心对象 | 回答的问题 | 是否进入主图 |
|---|---|---|---|
| 学习层 | Micro Topic、prerequisite | 学什么；先学什么；接着学什么 | 是 |
| 来源层 | Curriculum Anchor、source_ref | 依据什么；回哪里核对 | 否，进入详情 |
| 主题层 | Big Question、route、subject contribution、performance task | 为什么连接；各学科贡献什么；共同产出什么 | 否，作为主题入口与详情 |
| 应用层 | Theme、Activity Task、Material | 怎样设计活动与证据 | 否，作为资源链接 |
| 审阅层 | evidence_level、review_status | 哪些已确认；哪些仍是推断 | 否，进入详情与验证 |

## Full Alpha 0.3 的“全范围、分层展示”原则

本轮覆盖当前本地 12 门学科课标和 BQ1-BQ8，但不把全部来源内容一次铺进主图。产品分成“主题地图”和“课标覆盖”两种视图：

```text
8 个主题入口
  -> 选择真实问题并理解共同任务
  -> 查看各课标科目的内容贡献与核心素养
  -> 搜索 / 悬停节点
  -> 点击聚焦
  -> 高亮全部前置谱系
  -> 查看掌握证据与来源
  -> 点击直接前置或解锁项继续下钻
```

课标覆盖视图另外呈现“12 科 × 8 主题”矩阵、51 项核心素养和 182 个课程内容来源单元。这样既能证明本地语料是否覆盖，又不会把粗颗粒课标模块伪装成学习节点。

## 当前验收标准

- 首屏首先被感知为“学习世界”，而不是目录、表格或内部控制台。
- 点击任一节点后，能清楚看到全部前置数量、直接前置和直接解锁。
- 每个节点都有描述、学科、领域、阶段、至少一条掌握证据、一个诊断问题和来源指针。
- 每个节点都明确映射至少一个真实课标科目与相应核心素养；“综合节点”不被伪装成第十三门课标学科。
- 每个跨学科主题都有主题主旨、共同目标、至少三门学科的明确贡献和一个共同表现任务。
- 8 个主题完整覆盖 BQ1-BQ8；12 门课标科目都至少在一个主题中有实际节点贡献。
- 课标覆盖矩阵可逐科进入 51 项核心素养和 182 个来源单元。
- 每条先修边都有 `hard / soft` 与具体理由。
- 图无环、无自环、无孤立节点、无失效引用。
- 学科筛选、路径筛选、搜索、缩放、平移、连续下钻在桌面与移动端均可用。
- 任何结构推断都不冒充课标直接规定或专家共识。

## 下一阶段不应做什么

- 不先上 Neo4j、用户系统或后台编辑器。
- 不以“覆盖全部学科”代替节点质量。
- 不自动生成大量先修边后直接发布。
- 不把 activity task 改名为 micro topic。
- 不把 Big Questions 继续画成所有节点的共同父节点。
- 不新增独立学生产品表面。
- 不把静态 manifest 冒充可运行 Plugin。
- 不在网页、MCP 和目标宿主 Plugin 中维护三套课程逻辑。

## 下一阶段最值得做什么

1. 按 12 门学科拆分教师审阅包，优先检查 87 个节点的内容锚点、核心素养映射和 189 条边。
2. 把高优先级节点的来源从模块级页码细化到内容要求、学业要求或质量水平条目。
3. 为目前只有结构设计的 6 个新主题补教师共备样张和学生材料；保留现有两套 pilot 作为示范。
4. 修订稳定后，把通过审核的节点和关系从 `data/review/full/` 分批晋升到正式工作区。
5. 首个目标宿主已选为 Kimi Code：用第三方 Custom Plugin 封装已验证的只读 MCP；宿主模型负责生成活动，BunnyBook 负责提供可靠上下文。完成真实安装验收后，再考虑 GitHub 测试版与远程 MCP。
