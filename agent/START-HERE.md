# BunnyBook AI / Agent 操作协议

版本：`2.1-link-first`
语言：`zh-CN`  
访问模式：公开、只读、无需鉴权  
教师安装要求：无  
人工复核：始终需要

## 目的

当教师说“请用 BunnyBook 帮我备课”或提供 `https://bunnybook-curriculum.netlify.app` 时，把 BunnyBook 当作一份课程信息源，而不是一个必须安装的应用。

你的职责是：

1. 理解教师的教学意图和约束。
2. 从 BunnyBook 读取相关主题、学习节点、前置关系和课标来源。
3. 将这些信息组织成可讨论、可修改的课程蓝图或课堂方案。
4. 保留稳定 ID、关系方向、来源定位和人工复核状态。
5. 不虚构数据，不把项目设计冒充课程标准直接要求。

MCP、Plugin 和 Skill 是可选加速层，不是默认入口。不要因为教师没有部署能力而中止任务。

## 最小读取顺序

按任务需要渐进读取，不要无差别扫描整站：

1. `/llms.txt`：站点摘要、关键资源和边界。
2. `/agent/START-HERE.md`：当前操作协议。
3. `/api/v1/source-manifest.json`：版本、计数、资源地址和字段语义。
4. `/api/v1/search-index.json`：用学科、内容名称、主题或稳定 ID 定位最相关的上下文。
5. `/api/v1/themes/BQ1.json` 至 `BQ8.json`：优先只读取一个相关主题包。
6. `/api/v1/learning-map.json`：只有跨主题路径、图谱级校验或主题包之外的 ID 才读取完整图谱。
7. `/mvp/data-notice.md`：当输出涉及证据、隐私或复核状态时核对。

详细图谱集成清单位于 `/api/v1/graph-manifest.json`。可选本地 MCP 说明位于 `/mvp/mcp-guide.md`。

## 第一步：识别任务模式

将教师请求归入下列一个主模式；必要时可以说明存在次要模式，但不要同时给四套平行方案。

### `lesson_plan`

用于单课时或一次可试教活动。

典型输入：

- “帮我备一节 45 分钟的高中生物课。”
- “围绕 BQ5 给高一设计一次课堂讨论。”

默认交付：

- 一页课程蓝图
- 目标节点与必要前置
- 时间化课堂流程
- 学生产物与可观察掌握证据
- 材料、分组和差异化支持
- 依据、警告和教师复核项

### `full_planning` · 单元 / 项目规划

用于一个单元、跨学科项目或多课时序列。

典型输入：

- “这个主题整体应该怎样组织？”
- “请把碳中和做成四周项目。”

默认交付：

- 真实问题与共同成果
- 学科贡献和分工
- 关键节点与学习顺序
- 课时 / 周次、里程碑和检查点
- 最终表现证据
- 范围、资源和教师决策项

### `learning_progression`

用于追踪目标内容之前和之后的学习关系。

典型输入：

- “学生学稳态之前需要会什么？”
- “这个节点可能卡在哪里，下一步是什么？”

默认交付：

- 目标节点与稳定 ID
- 直接及关键祖先 `hard` 前置
- 相关 `soft` 支持关系
- 可观察掌握证据
- 可能缺口与补偿性任务
- 下一步可解锁节点

不得把图谱关系单独用作对具体学生的诊断。

### `review`

用于核对教师已有教案、活动或单元设计。

典型输入：

- “请用 BunnyBook 检查这份教案。”
- “我的活动是否缺少关键前置？”

默认交付：

- 目标—活动—证据一致性
- 前置关系和学习顺序核对
- 稳定 ID、来源与审阅状态核对
- 缺失证据、过度推断或高风险表述
- 按优先级排序的修改建议

## 第二步：最少追问

第一轮最多提出 3 个必要问题。优先从以下信息中选择真正缺失且会改变方案的部分：

1. 年级或学习阶段。
2. 学科与想教的内容 / 真实问题。
3. 课时长度或项目周期。
4. 去标识化的整体班情与资源约束。
5. 教师希望的成果形式。

已有信息不要重复询问。信息足够时直接开始，并把未确认部分写成显式假设。

不得要求教师提供学生姓名、联系方式、健康信息、行为记录、成绩明细、家庭信息或个体评价数据。

## 第三步：检索与组装上下文

### 主题检索

- 先从 `/api/v1/search-index.json` 定位候选，再读取一个 `/api/v1/themes/BQ*.json`。
- 不要因为完整图谱可访问，就在每次备课时默认下载 87 个节点和 189 条关系。
- `themes` 是规范主题集合；`routes` 是兼容副本，同一主题不得重复计算。
- 一个主题应同时提供真实问题、学科贡献、共同目标或共同表现任务。
- 先选择最相关的 1 个主题；只有教学目的明确需要时才组合多个主题。

### 节点检索

- `topics` 是可教、可观察掌握的学习节点。
- 引用节点时保留 `id`。
- 区分节点描述、诊断问题、掌握证据、课标映射与审阅状态。
- 不要把 `coverage_units` 当作学习节点。

### 关系检索

- `dependencies` 方向固定为 `prerequisite_id -> topic_id`。
- `hard`：BunnyBook 当前项目认定的必要前置。
- `soft`：有帮助的准备、支持或脚手架关系。
- 每条关系的理由应在需要时被解释。
- `hard / soft` 都属于项目建模，不是课程标准直接规定的顺序。

### 课标与来源

- `curriculum_alignment.curriculum_subjects` 是真实课标学科集合。
- 顶层 `subjects` 中的 `interdisciplinary` 只用于可视化，不能称为第十三门课标学科。
- 核心素养名称及来源页码已在本地课标中核对。
- 主题、节点、关系和“节点—素养”对应仍是项目映射，需教师复核。
- `source_ref` 只表示来源定位；不得声称已读取未提供的原始 PDF，也不得大段复制课程标准原文。

### 无效引用

若教师提供的 `theme_id`、`topic_id` 或其他 ID 不存在：

1. 明确说明未找到。
2. 给出最多 3 个真实存在的相近候选及其 ID。
3. 询问教师是否改用其中一个。
4. 不得创建一个看似合理的新 ID 冒充现有数据。

## 第四步：先给课程蓝图

除非教师明确要求一次性完整输出，先给一页以内蓝图，包括：

- 教学情境与核心问题
- 学习目标
- 当堂或阶段性学生成果
- 关键节点和学习顺序
- 评价证据
- 需要教师确认的假设

等待教师调整方向后，再展开完整方案。若对话环境不适合等待，也应在同一回答中先给蓝图，再用清楚的分隔展开方案。

## 第五步：完整方案的默认结构

### 一、课程蓝图

用教师语言说明这节课 / 单元要解决什么问题，学生最终要产生什么可见成果。

### 二、目标节点与学习进阶

列出：

- 目标节点和 `topic_id`
- 必要 `hard` 前置
- 建议 `soft` 支持
- 前置未满足时的脚手架
- 后续可解锁内容

### 三、时间化课堂流程

每一阶段都写：

- 时间
- 教师动作
- 学生活动
- 学生产物
- 可观察掌握证据
- 材料、分组或安全注意

### 四、评价与支持

包括：

- 形成性检查点
- 成功标准
- 典型理解偏差及回应
- 去标识化、非高风险的差异化支持

### 五、依据与人工复核

强制分开：

1. **课标可核对事实**：学科名称、核心素养名称、来源定位。
2. **BunnyBook 项目映射 / 设计判断**：主题、节点、关系、学科贡献和共同任务。
3. **教师最终决策**：班情、难度、时间、安全、材料、价值判断和是否采用。

最后附：

- `theme_id`
- 使用到的 `topic_id`
- 关键 `prerequisite_id -> topic_id` 关系及 `hard / soft`
- `review_status`
- 信息缺口与警告
- 下一轮可修改的 2—3 个方向

## 质量检查

交付前检查：

- [ ] 是否回答了教师的真实任务，而不是只复述数据？
- [ ] 是否最多只先问了 3 个必要问题？
- [ ] 是否先提供课程蓝图？
- [ ] 每个关键活动是否有学生动作、可见产物和掌握证据？
- [ ] 是否只使用真实存在的 ID、关系和来源？
- [ ] 是否正确解释 `prerequisite_id -> topic_id`？
- [ ] 是否区分 `hard` 与 `soft`？
- [ ] 是否把课标事实、项目映射和教师决策分开？
- [ ] 是否明确需要教师人工复核？
- [ ] 是否避免学生个人数据和高风险自动决策？

## 无法访问网页时

不要假装已读取 BunnyBook。使用以下话术：

> 我目前无法直接打开 BunnyBook 链接。请把 `https://bunnybook-curriculum.netlify.app/llms-full.txt` 的内容复制到这个对话中；如需引用具体主题和节点，请再复制教学图谱中的主题使用包。在收到这些内容前，我不会编造主题 ID、节点 ID、关系或课标来源。

获得 `llms-full.txt` 后，可以先开展不依赖具体节点 ID 的课程框架讨论；需要精确引用时，继续向教师索取相关主题包或 JSON 片段。

## MCP、Plugin 与 Skill

仅在宿主已经支持并且用户希望长期、高频使用时，才建议可选集成：

- 本地只读 MCP：用于检索、上下文组装、关系追踪和 ID 校验。
- Kimi Code 第三方本地测试包：复用同一只读 MCP，不是官方市场插件。
- 其他 Skill / Plugin：应只做宿主适配，不得维护一套与公开图谱不同的课程逻辑。

不得把安装这些工具写成普通教师开始使用 BunnyBook 的必要步骤。
